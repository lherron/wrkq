One-sentence thesis

Self-improvement is a harness contract.

The durable unit of improvement is not a better chat response. It is a validated change to memory, a reusable procedure, a searchable episode, a curation decision, or an automation signal that future agents can inspect and trust.

Primary decision Separate memory classes

Declarative facts, procedural skills, and episodic history stay distinct.

Primary invariant Review writes are constrained

Background self-modification should only use typed write surfaces.

Best feature to copy Post-task reflection

Task completion is the right learning boundary for praesidium.

Main risk Noisy procedural memory

Autonomous skills need provenance, reports, curation, and rollback.

Reading contract The strongest claim in the Hermes design is structural: self-improvement should be a separate lifecycle with typed artifacts and curation. The agent should not merely "remember better"; it should leave behind inspected, scoped, and reversible assets.

Ownership matrix

Make responsibility the dominant visual dimension.

Hermes is useful because each improvement surface has a different owner and failure profile. Praesidium should preserve that separation rather than merging everything into one memory bucket.

Plane Owns Must not do Praesidium analogue
Foreground agent Complete the user task, call tools, ask for clarification, produce visible answer. Rely on ad hoc memory writes as the only learning mechanism. Codex/Cody task execution inside wrkq and project worktrees.
Review worker Inspect completed work and propose durable learning. Continue the task, run unsafe tools, or recursively trigger itself. Post-wrkq-task reflection job with typed proposal output.
Memory layer Persist scoped declarative facts and retrieve relevant context. Store procedures, task diaries, or unscoped global rules. User, agent, and project memory stores with evidence links.
Skill layer Encode reusable procedures, scripts, templates, and references. Become a dumping ground for one-off task history. Repo/agent-local skills with provenance and usage tracking.
Curator Archive stale agent-created skills and propose consolidation. Delete by default or mutate user-authored/bundled skills automatically. Skill maintenance daemon with reports, pinning, and rollback.
Automation contexts Run cron, webhooks, subagents, and workers with explicit memory policy. Pollute user memory with unattended job output. hrc/acp/wrkq events feeding a learning-event stream.

Invariant ledger

Rules that should survive implementation drift.

These are the load-bearing rules to preserve if praesidium adapts Hermes' design. They are stated as release-gating constraints, not as general advice.

INV-01 - Separate memory classes

Copy

Declarative memory, procedural memory, and episodic memory are different assets.

A task transcript must not be promoted directly into user memory or a skill without classification, scope, and evidence.
  • Memory fact: stable preference or environment fact.
  • Skill: reusable procedure or runbook.
  • Episode: searchable history of what happened.

INV-02 - Review is constrained

Proof

Background review can improve the system, but only through narrow write APIs.

A reviewer must not have broad terminal/file authority when its job is memory or skill mutation.
  • Allowed: memory proposal, skill patch proposal, curation report.
  • Denied: arbitrary shell, recursive review, foreground task continuation.

INV-03 - Evidence precedes durability

Gate

Durable learning needs a source trail.

Every memory or skill write should link to the task, session, command, file, or user correction that justified it.
  • Reject writes with no evidence.
  • Prefer scoped updates over global rules.

INV-04 - Skills are inspectable assets

Copy

Skills are first-class procedural memory, not prompt fragments.

A skill must have metadata, provenance, state, usage counts, and a reversible history.
  • Support files are allowed but constrained.
  • Full skill content loads by progressive disclosure.

INV-05 - Archive before delete

Copy

Autonomous systems should not destroy their own procedural history by default.

Curators may stale or archive agent-created skills, but deletion requires explicit policy or human action.
  • Pinning protects important skills.
  • Rollback must be cheap.

INV-06 - Stable prompts remain stable

Proof

Mid-session writes should not silently rewrite the active instruction frame.

Prompt rebuilds and memory snapshot changes should be explicit events, not hidden side effects.
  • Protect prefix-cache behavior.
  • Make sessions reproducible.

Semantic modules

Hermes is a collection of learning surfaces.

Each module below has a claim, a useful design move, a praesidium adaptation, and a risk. This mirrors the recommended section contract: claim, rule, structured detail, exception, proof.

Declarative memory

Claim

Memory

Hermes uses built-in file memory plus optional provider memory. The built-in layer separates `MEMORY.md` from `USER.md`; providers add recall and user modeling.

Useful pattern

Adopt
  • Lock and atomically write local memory files.
  • Scan writes and loaded entries for prompt-injection patterns.
  • Inject retrieved memory transiently into the model call.
  • Scrub retrieved memory from visible output and future sync.

Praesidium modification

Adjust

Use scoped memory objects: user, agent, and project. Require evidence links and confidence. Make external provider health visible instead of only best-effort debug noise.

Procedural memory

Claim

Skills

Skills are Hermes' strongest self-improvement layer. They convert experience into reusable procedures with optional references, templates, scripts, and assets.

Useful pattern

Adopt
  • Keep only compact skill metadata in the default prompt.
  • Load full skill instructions with `skill_view`.
  • Record skill provenance, usage, patches, state, and pinning.
  • Clear prompt-skill caches after mutation.

Praesidium modification

Adjust

Hermes allows reviewer agents to call skill write tools directly. Praesidium should prefer typed proposals, validation, and apply/propose modes before mutation.

Background review

Claim

Loop

Hermes forks a reviewer after selected turns. The reviewer is restricted to memory and skill tools and runs after the user-visible answer is delivered.

Useful pattern

Adopt
  • Review should not compete with foreground latency.
  • Review should not ingest itself into external memory.
  • Review should not recursively trigger more review.
  • Review should summarize what it changed.

Praesidium modification

Adjust

Trigger review from wrkq lifecycle events, user corrections, repeated tool failures, subagent discoveries, and smoke test outcomes. Periodic counters should be fallback, not the only signal.

Curator

Claim

Hygiene

Hermes offsets autonomous skill creation with autonomous skill maintenance. The curator marks skills stale, archives old ones, proposes consolidation, writes reports, and supports rollback.

Useful pattern

Adopt
  • Manage only agent-created skills automatically.
  • Never delete by default.
  • Respect pinned, bundled, and imported skills.
  • Write a human-readable report for every run.

Praesidium modification

Adjust

Start in propose mode. Hermes' curator is intentionally aggressive about umbrella skills; praesidium should begin conservatively and require stronger evidence for consolidation.

Automation contexts

Claim

Context

Hermes treats subagents, cron, webhooks, and kanban workers as distinct harness contexts with different memory policies.

Useful pattern

Adopt
  • Subagents run isolated and return summaries.
  • Cron jobs can load skills and produce searchable sessions.
  • Webhook routes can load skills and deliver results.
  • Automated contexts often run with memory writes disabled.

Praesidium modification

Adjust

Feed automation output into structured learning events. Do not rely on unattended jobs writing durable memory directly.

Episodic recall

Claim

Search

Hermes session search is a deterministic SQLite FTS recall surface. It is cheap, lineage-aware, and useful for named prior work.

Useful pattern

Adopt
  • Expose browse, query, and scroll-around-message modes.
  • Exclude current session lineage when appropriate.
  • Use session search before claiming no precedent exists.

Praesidium modification

Adjust

Index wrkq tasks, comments, hrc transcripts, acp messages, service logs, and handoffs. Add semantic search later; lexical recall is enough for task IDs, filenames, commands, and errors.

Target design

Praesidium should learn through typed events and validated writes.

The most important change from Hermes is to put a structured proposal layer between model judgment and mutation. The reviewer can recommend; a deterministic applier validates and records.

01 Event

Task complete, correction, failure, subagent discovery, cron result.

02 Evidence

Collect task, transcript, command, file, log, and smoke test links.

03 Reviewer

Classify durable learning and emit structured proposals.

04 Validator

Check schema, scope, policy, paths, size, and security.

05 Write

Apply memory or skill update, or queue for approval.

06 Curate

Track usage, stale/archive, report, and make future prompt/search better.

Current risk

Learning is implied by chat continuity, scattered notes, or manual agent discipline. Durable improvements depend on whether the active agent remembers to write them down.

Target behavior

The harness emits learning events. Reviewers produce typed proposals. Validators apply safe writes. Curators manage drift. Future agents discover the result through prompt snapshots, skills, and search.

Review mode policy
Mode Behavior Best initial use
Observe Write reports only. Early rollout and calibration.
Propose Create pending changes for review. Skill creation and broad behavior changes.
Apply Apply safe validated changes directly. Low-risk project memory and narrow skill patches.

Implementation plan

Build the learning system in six phases.

This sequence starts with evidence and recall, then adds typed memory, skills, reflection, curation, and automation integration. It avoids building a large memory platform before the evidence model exists.

1Evidence and search

  • Index wrkq tasks, comments, hrc transcripts, and acp messages.
  • Search by task id, file, command, error, and phrase.
  • Store exact source links for review evidence.

2Typed memory

  • Add user, agent, and project memory scopes.
  • Add typed write/list/read/remove commands.
  • Scan memory writes and snapshot memory into prompts.

3Skills

  • Define skill directory format and index.
  • Add `skill_view` and create/patch operations.
  • Track provenance, usage, and task/session evidence.

4Reflection worker

  • Run on task completion and explicit correction events.
  • Emit structured proposed writes.
  • Apply safe memory and queue skill changes in propose mode.

5Curator

  • Add stale and archive transitions for agent-created skills.
  • Add reports, rollback, pinning, and conservative consolidation.
  • Never mutate user-authored or bundled skills automatically.

6Automation integration

  • Feed subagent, cron, service, and worker results into learning events.
  • Promote successful scripts into skill support files.
  • Track skill failures and validator results.

Proof layer

Acceptance gates turn architecture into testable behavior.

These gates are the minimum evidence that a praesidium self-improvement system is working safely. They should be wired to actual smoke tests, CLI checks, and audit queries.

Gate Required evidence Owner Failure means
Typed proposal before mutation Review output is valid YAML/JSON and stored before apply. Review worker Model judgment can mutate durable state invisibly.
Evidence-linked memory write Every memory object links to task/session/message/file evidence. Memory layer Durable facts cannot be audited or challenged.
Skill provenance captured Created_by, source task, usage, patch count, and state are queryable. Skill layer Curator cannot distinguish agent-created assets.
Review tool restriction Background reviewer cannot run arbitrary shell or broad file edits. Harness Self-improvement path becomes a privileged execution path.
Archive rollback Archived skill can be restored with metadata intact. Curator Curation is destructive.
Provider degraded mode visible Status command reports external memory health and last error. Memory provider Recall silently degrades and agents overtrust context.
  • Review on wrkq task completion produces a stored review run.
  • User correction creates or proposes a scoped memory update.
  • Repeated command failure can trigger a skill patch proposal.
  • Skill prompt index excludes full skill bodies by default.
  • Curator dry-run report lists candidate stale skills without applying.
  • Session search finds prior tasks by task id, file path, command, and error text.

Failure semantics

Most risks are governance failures, not retrieval failures.

Hermes already shows the main hazards: poisoned memory, too many narrow skills, broad rules from one incident, stale procedures, invisible mutation, context leakage, subagent knowledge loss, and curator damage.

Failure mode Symptom Mitigation
Memory poisoning A malicious or accidental instruction becomes durable behavior. Threat scan, source evidence, scoped memory, human review for broad behavior rules.
Skill sprawl Many narrow overlapping skills compete for attention. Prefer patching, track similarity, curate, pin, archive instead of delete.
Overgeneralization A one-off failure becomes a global rule. Require scope, confidence, evidence, and expiration for caveats.
Stale procedures A skill encodes old commands or service behavior. Track validation time, skill failures, smoke tests, and stale state.
Invisible mutation The agent changes skills or memory without a visible trail. Audit log, diff viewer, review reports, propose mode.
Context pollution Retrieved memory is copied into transcripts and re-ingested. Memory-context wrappers, sanitization, output scrubber, source labels.
Subagent knowledge loss Child agents find useful facts but parent summaries omit them. Structured child result fields and delegation-triggered review.
Curation damage A useful skill is archived or over-consolidated. Dry-run, conservative thresholds, pinning, rollback, archive-only default.

Recommended review prompt for praesidium 
You are the praesidium self-improvement reviewer.

Your job is not to continue the task. Your job is to decide whether this
completed work produced durable learning.

Classify each possible update as one of:
- user_memory
- agent_memory
- project_memory
- skill_create
- skill_patch
- episodic_only
- no_update

Only propose updates that are:
- durable beyond this task
- scoped correctly
- supported by concrete evidence
- useful for future agents

Do not create a skill for one-off task history.
Do not create broad rules from transient failures.
Prefer patching an existing skill over creating a new one.

Return structured YAML only.
Final recommendation

Build praesidium self-improvement around a durable learning pipeline: 

event -> evidence collection -> reviewer -> typed proposal -> validator
      -> memory/skill write -> audit log -> curator -> future prompt/search

Keep write APIs narrow, audit trails strong, and memory types separate. Let agents learn procedures, but make every durable procedure inspectable, scoped, versioned, and reversible.

PBC Combined Task and Workflow State Transition Table

Source: pbc/workflow-template.json, workflow pbc-progressive-refinement@5.

The PBC template now carries plain-English descriptions on workflow states, transitions, and outcomes. The workflow state and transition descriptions below come directly from the template.

Current implementation note: this PBC workflow template declares workflow transitions, evidence requirements, descriptions, and blocking obligations, but it still does not declare task-state effects. The wrkq task state column below remains the intended coarse task lifecycle policy that would need a native set_task_state effect or an effect handler that calls wrkq set TASK --state STATE.

Workflow State Descriptions

Workflow state wrkq task state Description from template
open/intake open Raw one-line feedback has landed but has not yet been normalized into a Behavior Note.
active/behavior_note in_progress Feedback is normalized into a Behavior Note; the agent decides whether one clarification is needed before drafting.
waiting/clarification blocked Blocked on the product owner answering the single highest-leverage clarification question.
active/pbc_draft in_progress A compact PBC has been drafted and is ready for a pressure pass.
active/pressure in_progress A pressure pass is being run against the draft PBC to test it for readiness, needed patches, or vagueness.
waiting/patch_decision blocked Blocked on the product owner deciding whether to finalize with the pressure patch or send the PBC back for revision.
closed/finalized completed Terminal success: the final PBC is accepted and downstream work/test/design seeds can be derived.
closed/disposed cancelled Terminal disposal: the feedback was closed without a finalized PBC (won't fix, duplicate, unclear, or out of scope).

State Mapping Policy

Workflow state pattern wrkq task state Lifecycle meaning
open/intake open Feedback is captured but work has not begun.
active/* in_progress The workflow is actively producing or revising the Behavior Note, PBC draft, or pressure pass.
waiting/* blocked The workflow is blocked on a product-owner clarification or patch decision.
closed/finalized completed A final PBC has been accepted and stored.
closed/disposed cancelled The feedback is intentionally closed without a final PBC.

Transition Table

# Transition Description from template Required gate Outcome Workflow state change wrkq task state change
0 Attach workflow Create a workflow instance from pbc-progressive-refinement@5. Attach the template to a wrkq task. Initial workflow instance state. - -> open/intake open
1 normalize_feedback Normalize the raw one-line feedback into a Behavior Note, capturing the normalized signal, likely type, and candidate clarification question. intake_metadata normalized: Feedback was normalized; advance to the Behavior Note state. open/intake -> active/behavior_note open -> in_progress
2 ask_clarification Pre-interview analysis flagged that clarification is needed; raise the single highest-leverage question and wait for the product owner. behavior_note and pre_interview_analysis.clarification_needed=true needs_answer: Clarification is required; move to the waiting state and open a blocking obligation on the product owner. active/behavior_note -> waiting/clarification in_progress -> blocked
3 draft_pbc Enough is known without clarification; draft the compact PBC directly from the Behavior Note. behavior_note and pre_interview_analysis.clarification_needed=false drafted: PBC was drafted; advance to the draft state ready for a pressure pass. active/behavior_note -> active/pbc_draft Stay in_progress
4 answer_clarification The product owner answered the clarification (or accepted the default); record it and proceed to drafting the PBC. clarification_response evidence and satisfied clarification_response obligation. answered: Clarification satisfied; advance to the draft state. waiting/clarification -> active/pbc_draft blocked -> in_progress
5 run_pressure_pass Run the compact pressure pass against the draft PBC to produce a verdict, tighten list, and patch. pbc_draft pressure_ready: Pressure pass started; advance to the pressure state where its verdict routes the next step. active/pbc_draft -> active/pressure Stay in_progress
6 finalize_ready_pbc Pressure pass returned a ready verdict; finalize the PBC and close the task as finalized. pressure_pass.verdict=ready and pbc_final finalized: PBC accepted; transition to the terminal finalized state. active/pressure -> closed/finalized in_progress -> completed
7 request_patch_decision Pressure pass requested a patch; route to the product owner to accept, adjust, reject, or waive it. pressure_pass.verdict=needs_patch needs_decision: A patch decision is required; move to the waiting state and open a blocking obligation on the product owner. active/pressure -> waiting/patch_decision in_progress -> blocked
8 revise_too_vague_pbc Pressure pass judged the PBC too vague; send it back to drafting without a product-owner decision. pressure_pass.verdict=too_vague revise: PBC needs more work; send it back to the draft state for another iteration. active/pressure -> active/pbc_draft Stay in_progress
9 finalize_after_patch_decision Product owner chose to finalize after reviewing the pressure patch; finalize the PBC and close the task. patch_decision.route=finalize, satisfied patch_decision obligation, and pbc_final. finalized: PBC accepted; transition to the terminal finalized state. waiting/patch_decision -> closed/finalized blocked -> completed
10 revise_after_patch_decision Product owner chose revision after reviewing the pressure patch; send the PBC back to drafting. patch_decision.route=revise and satisfied patch_decision obligation. revise: PBC needs more work; send it back to the draft state for another iteration. waiting/patch_decision -> active/pbc_draft blocked -> in_progress
11 dispose_from_behavior_note Dispose the feedback directly from the Behavior Note state when a disposition decision closes it without a PBC. disposition_decision disposed: Feedback closed without a finalized PBC; transition to the terminal disposed state. active/behavior_note -> closed/disposed in_progress -> cancelled
12 dispose_from_pbc_draft Dispose the feedback from the draft state when a disposition decision closes it without finalizing the PBC. disposition_decision disposed: Feedback closed without a finalized PBC; transition to the terminal disposed state. active/pbc_draft -> closed/disposed in_progress -> cancelled
13 dispose_from_pressure Dispose the feedback from the pressure state when a disposition decision closes it instead of patching or finalizing. disposition_decision disposed: Feedback closed without a finalized PBC; transition to the terminal disposed state. active/pressure -> closed/disposed in_progress -> cancelled

Effect Needed To Make Task State Real

To make the task state changes above happen automatically, each transition outcome that changes coarse task state needs a side effect. A native effect would be preferable to a shell hook. 

{
  "kind": "set_task_state",
  "role": "system",
  "data": {
    "state": "in_progress"
  }
}

Until that exists, an effect handler could receive the task id and run wrkq set "$task_id" --state "$state", then acknowledge the effect.

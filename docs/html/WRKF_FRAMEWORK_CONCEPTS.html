Workflow engine contract

wrkf is a revisioned state tuple plus an append-only decision ledger.

Each transition starts from a declared {status, phase} tuple, admits only specific roles, branches on check outcomes, then records the chosen state, effects, obligations, and event metadata for safe retries.

State
State = {status, phase, outcome?}
The initial state and every outcome target must be listed in the template's declared states.
Transition
from -> checked outcomes -> to
Runtime admission checks role, revision, context hash, blockers, check runs, guards, and idempotency.
Scheduler
wrkf next ranks one best next move
Actions are deterministic objects with owner, command, blockers, expected state, and guardrails.

observer agent:cody External reviewer for completion claims; bound with wrkf run bind before observer effects are delivered.

03 Transitions

Transitions are not one edge each. They are role-gated branch sets. A check outcome selects a branch, and a branch may loop to the same state, move forward, enter recovery, or emit effects and obligations.

planning_to_architect_review {active, planning} Runs plan_ready. Outcome plan_ready moves to {waiting, architect_review} and wakes the architect; revise_plan or missing_plan loops to planning; other outcomes call supervisor and enter error.
impl_results_terminal {waiting, impl_results} Requires stacked_terminal and impl_verified. Success moves to {active, green_verified}; assignee closure gaps and missing evidence notify implementer; scope drift wakes architect; stash collision enters supervisor recovery.
submit_completion_claim {active, report} Requires coordinator smoke and report readiness. Success moves to {waiting, review_pending} and emits request_observer_review with guardrails for external audit.
report_complete {waiting, review_pending} Observer-owned. Accepted or accepted-with-followups closes completed; needs-work wakes coordinator and creates address_observer_rejection; blocked enters {waiting, blocked} with supervisor obligation.
blocked_resolved / recover_from_error recovery target fact Supervisor or coordinator chooses a declared target via recovery.target. Unknown target routes back to error or closed failed.

04 Checks and Hooks

A check is a typed hook or predicate whose verdict and outcome become branch input. Hook checks execute deterministic local scripts from the hook catalog; exit codes are mapped through each template check's exitMap.

plan_ready exit map

validate_plan_ready.sh requires source spec and decomposition plan evidence. Exit 0 is pass, 11 requests plan revision, 20 reports missing plan, and 50 routes to supervisor recovery.

0 -> pass / plan_ready 11 -> fail / revise_plan 20 -> fail / missing_plan 50 -> error / supervisor_recovery

Hook catalog

The local catalog names deterministic scripts such as validate_red_verified.sh, validate_impl_verified.sh, validate_live_smoke.sh, validate_coordinator_smoke_verified.sh, and validate_observer_completion_review.sh.

stdin: json stdout: exit_code cwd: template_dir
Evidence is the check surface: hooks consume task facts, evidence rows, obligations, and workflow state. The validator decides exit code; the template decides what that exit code means for branch selection.

05 Ledger Lifecycles

wrkf separates durable artifacts from duties and side effects. Evidence is append-only. Obligations gate progress. Effects are delivery jobs with retryable lifecycle state.

Evidence

Typed artifacts

Examples include red_evidence, coordinator_smoke_execution, completion_claim, and observer_completion_review. Evidence has facts for routing and data for richer payloads.

Effects

At-least-once delivery

Effects begin pending; handlers deliver, ack, fail, and retry. Observer review is delivered through a registered effect handler and bound role delivery ref.

Obligations

Outstanding duties

Obligations are open until satisfied, waived, or cancelled. Blocking obligations stop transitions; nonblocking obligations still appear in wrkf next.

06 Next Action Model

The declarative model says which class of action wins. The current service turns that into ranked DTOs with owner, command, blockers, expected state, and guardrails.

1 hard_block_recovery Supervisor or coordinator action needed for blocked/error state, failed effect, stale binding, or hard obligation.
2 owned_transition_available A legal transition from the current state is available for the requested role; command includes --expect-revision.
3 missing_evidence_collection A transition or check input requires a missing evidence kind, so collect the source truth before checking again.
4 dispatch_ready_worker A worker effect or role wakeup is ready once the role is bound to a delivery ref.
5 wait_for_external_owner The best move belongs to architect, implementer, red author, observer, or supervisor.
6 nonblocking_followup Open nonblocking obligations such as observer follow-up or rejection remediation remain visible without preventing all progress.
Delivery reference: the model's template is {actor}@{project}:{taskId} with lane default main. wrkf run bind TASK ROLE HANDLE persists the role-to-handle binding.

Transition

TransitionSpec, OutcomeCase, and Predicate

The branch contract that moves an instance from one declared tuple to another.

from/to by checks 
type TransitionSpec = { // Template transition evaluated from the current instance state.
  id: string // Stable transition id used by wrkf transition and check commands.
  from: State // Source tuple that must match the current instance state.
  by: string[] // Allowed roles; validation accepts template roles plus supervisor and system.
  responsibility?: ResponsibilitySpec // Optional owner resolution metadata for scheduling.
  guards?: Predicate[] // Predicates that must pass before any outcome can commit.
  requires?: RequirementSpec[] // Evidence or obligation prerequisites checked before guards and outcomes.
  checks?: string[] // Named check ids whose latest or freshly run outcomes feed branch predicates.
  outcomes: OutcomeCase[] // Ordered branch set; first matching predicate selects target, effects, and obligations.
  hooks?: Record<string, HookRef[]> // Optional transition-local hooks grouped by lifecycle point.
}

type OutcomeCase = { // One possible branch under a transition.
  id: string // Stable outcome id recorded in the transition event payload.
  when: Predicate // Branch predicate such as checkOutcome, all, otherwise, or factEquals.
  to: State // Target tuple that must be declared in template states.
  effects?: EffectSpec[] // Side effects inserted as pending workflow_effects rows after commit.
  obligations?: ObligationCreateSpec[] // Duties inserted as open workflow_obligations rows after commit.
}

type Predicate = { // Recursive predicate language used by guards, outcomes, and predicate checks.
  always?: boolean // Unconditional true branch.
  otherwise?: boolean // Fallback branch that must be the final outcome when true.
  all?: Predicate[] // Conjunction over child predicates.
  any?: Predicate[] // Disjunction over child predicates.
  not?: Predicate // Negation over one child predicate.
  checkVerdict?: { check: string; is: string } // Matches a named check run verdict.
  checkOutcome?: { check: string; is: string } // Matches a named check run outcome used for branch routing.
  evidenceExists?: EvidenceRequirementSpec // Tests whether matching evidence exists.
  obligationStatus?: ObligationPredicate // Tests whether an obligation has the requested status.
  factEquals?: { path: string; value: unknown } // Compares a task or workflow fact path to a literal value.
}

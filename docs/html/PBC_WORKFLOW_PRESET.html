wrkf.workflow-template.v0 / pbc-progressive-refinement@4

The PBC preset turns one-line feedback into a compact behavior contract.

It deliberately avoids multiplying product artifacts: the agent creates a Behavior Note, decides whether one product-owner answer is needed, drafts a PBC, pressure-tests it, and either finalizes, revises, or disposes the work.

01 Lifecycle

The preset is a progressive refinement loop. It starts with raw feedback, writes a tentative Behavior Note, drafts a PBC only after enough confidence exists, pressure-tests it, and then either finalizes or loops.

01 / intake

Normalize feedback

Record intake_metadata, then move from {open, intake} to {active, behavior_note}.

normalize_feedback
02 / behavior_note

Write the Behavior Note

The task description holds signal, problem, impact, tentative direction, disposition, and one open question.

behavior_note
03 / optional wait

Ask one question

If pre_interview_analysis.clarification_needed is true, create a blocking product-owner clarification obligation.

clarification_response
04 / pbc_draft

Draft the PBC

The task specification becomes promise, observable behavior, rules, states, non-scope, and derivation seeds.

pbc_draft
05 / pressure

Pressure pass

A compact review emits verdict ready, needs_patch, or too_vague.

pressure_pass
06 / terminal

Finalize or dispose

Ready PBCs close as finalized. Out-of-scope, duplicates, unclear, or wont-fix items close as disposed.

pbc_final
Core design rule: the workflow asks for product-owner input only when a single question or patch decision materially changes confidence. Otherwise the agent keeps refining locally.

02 Decision Points

The transition graph is mostly linear until evidence facts force a branch. These are the branches that determine whether the preset waits, loops, finalizes, or disposes.

normalize_feedback {open, intake} -> {active, behavior_note} Requires intake_metadata. Either role may normalize raw feedback into a structured starting point.
ask_clarification {active, behavior_note} -> {waiting, clarification} Requires behavior_note plus pre_interview_analysis where clarification_needed=true. Creates a blocking clarification_response obligation for product owner.
draft_pbc {active, behavior_note} -> {active, pbc_draft} Requires clarification_needed=false. The agent can proceed without waiting when the default direction is good enough.
answer_clarification {waiting, clarification} -> {active, pbc_draft} Requires clarification_response evidence and a satisfied clarification obligation.
run_pressure_pass {active, pbc_draft} -> {active, pressure} Requires pbc_draft. The review is intentionally compact: verdict, tighten list, and patch.
finalize_ready_pbc {active, pressure} -> {closed, finalized} Requires pressure_pass.verdict=ready and pbc_final.
request_patch_decision {active, pressure} -> {waiting, patch_decision} Requires pressure_pass.verdict=needs_patch. Creates a blocking product-owner patch decision obligation.
revise_too_vague_pbc {active, pressure} -> {active, pbc_draft} Requires pressure_pass.verdict=too_vague. The agent loops back to drafting instead of asking for a patch decision.
finalize_after_patch_decision {waiting, patch_decision} -> {closed, finalized} Requires patch_decision.route=finalize, satisfied obligation, and pbc_final.
revise_after_patch_decision {waiting, patch_decision} -> {active, pbc_draft} Requires patch_decision.route=revise and a satisfied patch decision obligation.
dispose_from_* behavior_note | pbc_draft | pressure -> {closed, disposed} Requires disposition_decision. Disposition facts distinguish wont_fix, duplicate, unclear, and out_of_scope.

03 Evidence

The preset keeps evidence small and typed. Rich artifact text belongs in task description/specification; facts are only the branch selectors that wrkf must reason over.

intake_metadata

Raw one-line feedback plus normalized signal, likely type, and candidate highest-leverage question.

behavior_note

The Behavior Note stored in the wrkq task description.

pre_interview_analysis

Agent analysis of what is known, what remains uncertain, and whether clarification is needed.

required: clarification_needed:boolean

clarification_response

The product-owner answer to the one clarification question.

pbc_draft

The draft PBC stored in the wrkq task specification.

pressure_pass

Compact pressure pass verdict, tighten list, and patch.

verdict: ready | needs_patch | too_vague

patch_decision

Product-owner decision after a pressure pass requests a patch.

route: finalize | revise

pbc_final

The finalized PBC stored in the wrkq task specification.

disposition_decision

Reason this feedback is closed without a finalized PBC.

resolution: wont_fix | duplicate | unclear | out_of_scope
clarification_response

Blocking wait

When clarification is needed, the workflow creates a blocking product-owner duty. The answer transition requires both the evidence and the satisfied obligation.

patch_decision

Patch gate

When pressure says the PBC needs a patch, the workflow waits for product owner to accept, adjust, reject, or waive the patch before finalizing or revising.

04 Artifact Templates

The markdown templates constrain the amount of product writing. They keep each artifact focused on behavior and branch-driving facts.

task description

Behavior Note

  • Signal: the one-line feedback or observed issue.
  • Problem: what the user tried and what broke.
  • Impact: why it matters.
  • Expected direction: tentative product expectation.
  • Disposition and one open question.
task specification

PBC

  • Promise: plain-language product commitment.
  • Behavior: observable when/then results.
  • Rules: always, never, visibility, recovery, and safety constraints.
  • States: empty, ready, working, failed.
  • Not included plus seeds for downstream derivation.
review artifact

Pressure Pass

  • Verdict: ready, needs patch, or too vague.
  • Tighten: ambiguity, missing state/rule, or scope leak.
  • Patch: concrete replacements or additions.

Routing facts

PBCDecisionFacts

The branch-driving facts declared under evidence kind contracts and transition requirements.

clarify pressure close 
type PBCDecisionFacts = { // Minimal facts wrkf uses to route the PBC workflow.
  pre_interview_analysis: { // Analysis evidence recorded before asking product owner.
    clarification_needed: boolean // True sends the workflow to waiting/clarification; false allows draft_pbc.
  }
  pressure_pass: { // Review evidence emitted after pbc_draft.
    verdict: 'ready' | 'needs_patch' | 'too_vague' // Ready finalizes, needs_patch waits for owner, too_vague loops to draft.
  }
  patch_decision: { // Product-owner decision after a needs_patch pressure pass.
    route: 'finalize' | 'revise' // Finalize requires pbc_final; revise returns to pbc_draft.
  }
  disposition_decision: { // Closure evidence for items that should not become finalized PBCs.
    resolution: 'wont_fix' | 'duplicate' | 'unclear' | 'out_of_scope' // Reason the workflow closes as disposed.
  }
}

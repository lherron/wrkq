wrkq task plane -> wrkf workflow plane

Public contract shapes for tasks, handoffs, and workflow routing.

wrkq owns project/task collaboration records. wrkf owns workflow templates, instances, routing evidence, checks, effects, obligations, and next-action suggestions.

Task collaboration
wrkq --json
Tasks, containers, comments, attachments, handoffs, event log, and agent scope diagnostics.
Workflow execution
wrkf --json
Templates, instances, transitions, checks, evidence, obligations, effects, runs, hooks, and supervisor actions.
Compatibility rule
DTO fields are additive by default
Consumers should tolerate unknown fields and use ids, etags, revisions, and context hashes for concurrency-sensitive operations.

01 Surface Map

The public machine contract is split by binary and responsibility. wrkq is the safe collaboration surface for agents and humans. wrkf is the workflow state machine layered over wrkq tasks.

wrkq

Collaboration records

Resource CRUD, comments, attachments, handoffs, search, history, and agent scope diagnostics.

wrkf

Workflow records

Template validation/install, task attachment, state inspection, transitions, checks, evidence, effects, obligations, and next actions.

Format

DTO notation

Types use TypeScript-like DTO syntax over the actual JSON field names emitted by the CLI and current Go structs.

Stability boundary Public consumers should prefer --json, --ndjson, --tsv, --columns, and --porcelain over parsing human tables or markdown bodies.

02 wrkq Command Surface

The wrkq CLI exposes resource and collaboration operations. Most commands support structured output; mutating commands require actor attribution and support optimistic concurrency where the target has an etag.

Agent + human surface

Resource command ledger

Command families grouped by their public DTO surface. Human-friendly aliases are not exhaustive here; the contract is the resource shape returned by structured output.

--json--ndjsonetag
Command family DTOs Purpose
ls, tree, find, cat, stat TaskDTO, ContainerDTO, CommentDTO Discover and read task/container resources. cat --json is the richest task read shape.
touch, set, mv, rm, restore TaskDTO, ContainerDTO Create, update, move, archive/delete, and restore resources. Mutations accept --if-match where etags are available.
comment * CommentDTO Append immutable task comments and soft/hard-delete them through dedicated comment commands.
attach * AttachmentDTO Manage attachment metadata and filesystem-backed payloads under the configured attachment directory.
handoff * HandoffDTO, HandoffPageDTO Create, list, read, acknowledge, and search agent session continuity records scoped to (agent, project).
watch, log, diff, search EventDTO, SearchResultDTO Stream changes, inspect history, compare resources, and query indexed task/comment content.

03 wrkf Command Surface

wrkf commands operate on workflow templates and workflow instances attached to wrkq tasks. JSON output is the primary machine contract for orchestration agents.

Workflow surface

Workflow command ledger

The command families map directly to workflow DTOs. Transition safety is driven by revision, context hash, task document hash, check ids, and idempotency keys.

--jsonrevisioncontext
Command family DTOs Purpose

task attach/inspect/timeline/refresh/sync-meta WorkflowInstanceDTO, WorkflowEventDTO Attach task instances, inspect current workflow state, refresh context, and synchronize task metadata projections.
next NextActionResponseDTO Return ranked actions, blocked transitions, open obligations, and pending effects for the current role.

evidence/check/obligation/effect/run/hook EvidenceDTO, CheckRunDTO, ObligationDTO, EffectDTO, RunDTO, HookCatalogDTO Operate supporting runtime records that influence transitions and next-action generation.
supervisor * EffectDTO, ObligationDTO, TransitionResultDTO Create escalation effects, create obligations, or force supervisor-mediated transition/retry actions.

04 wrkq Resource DTOs

Core wrkq DTOs are filesystem-flavored resources backed by SQLite rows. Container, comment, and attachment DTOs are each kept as standalone full-width contract objects.

Resource DTO

TaskDTO

Task records are the primary work item. Friendly ids are human-stable, UUIDs are storage-stable, and etags protect concurrent mutation.

T-etagstate 
type TaskState = 'idea' | 'draft' | 'open' | 'in_progress' | 'blocked' | 'completed' | 'cancelled' | 'archived' | 'deleted' // Lifecycle values accepted by task state filters and mutations.
type TaskKind = 'task' | 'subtask' | 'spike' | 'bug' | 'chore' // Work item classification stored on TaskDTO.kind.

type TaskDTO = { // Primary work item returned by task discovery, reads, creates, and updates.
  id: string // Friendly task id such as T-00001.
  uuid: string // Stable storage identity for joins, attachments, and history.
  path?: string // Resolved container/task path emitted by list and read commands.
  slug: string // Lowercase path segment unique among sibling tasks.
  title: string // Human-readable task title.
  project_uuid: string // Owning container UUID.
  parent_task_uuid?: string // Parent task UUID when this task is modeled as a subtask.
  assignee_actor_uuid?: string // Assigned actor UUID when work has an owner.
  state: TaskState // Workflow lifecycle state persisted on the task row.
  priority: 1 | 2 | 3 | 4 // Priority where 1 is highest and 4 is lowest.
  kind: TaskKind // Task type used for filtering and display.
  start_at?: string // Optional scheduled start timestamp.
  due_at?: string // Optional due timestamp.
  labels?: string[] | string // Label set; raw store-shaped outputs may expose encoded JSON.
  meta?: Record<string, unknown> | string // Task metadata; raw store-shaped outputs may expose encoded JSON.
  description: string // Main task body.
  specification?: string // Optional structured specification body.
  etag: number // Optimistic concurrency token incremented on mutation.
  created_at: string // Creation timestamp.
  updated_at: string // Last mutation timestamp.
  completed_at?: string // Completion timestamp when the state reached completed.
  archived_at?: string // Soft archive timestamp that hides the task from default reads.
  deleted_at?: string // Soft delete timestamp when the task was deleted.
  comments?: CommentDTO[] // Included by rich task reads such as cat --json.
  attachments?: AttachmentDTO[] // Included by rich task reads when attachment metadata is loaded.
  relations?: TaskRelationDTO[] // Included by rich task reads when relation data is loaded.
}

type TaskRelationDTO = { // Directed relation between two task records.
  id: string // Friendly relation id when surfaced by resource reads.
  uuid: string // Stable relation storage identity.
  from_task_uuid: string // Source task UUID.
  to_task_uuid: string // Target task UUID.
  kind: string // Relation kind such as blocks, relates, or parent-child.
  created_at: string // Relation creation timestamp.
}

DTO catalog for stable machine-facing JSON outputs. Human markdown, porcelain text, and interactive editing formats are intentionally summarized rather than typed as JSON contracts.
wrkq task plane -> wrkf workflow plane

Public contract shapes for tasks, handoffs, bundles, and workflow routing.

wrkq owns project/task collaboration records. wrkf owns workflow templates, instances, routing evidence, checks, effects, obligations, and next-action suggestions. Both expose stable machine surfaces through JSON-oriented CLI output.

Task collaboration
wrkq --json
Tasks, containers, comments, attachments, handoffs, event log, bundles, and agent scope diagnostics.
Workflow execution
wrkf --json
Templates, instances, transitions, checks, evidence, obligations, effects, runs, hooks, and supervisor actions.
Compatibility rule
DTO fields are additive by default
Consumers should tolerate unknown fields and rely on IDs, etags, revisions, and context hashes for concurrency-sensitive operations.

01 Surface Map

The public machine contract is split by binary and responsibility. wrkq is the safe collaboration surface for agents and humans. wrkf is the workflow state machine layered over wrkq tasks.

wrkq

Collaboration records

Resource CRUD, comments, attachments, handoffs, search, history, bundles, and agent scope diagnostics.

wrkf

Workflow records

Template validation/install, task attachment, state inspection, transition, checks, evidence, effects, obligations, and next actions.

Format

DTO notation

Types below use TypeScript-like DTO syntax over the actual JSON field names emitted by the CLI and current Go structs.

Stability boundary Public consumers should prefer --json, --ndjson, --tsv, --columns, and --porcelain over parsing human tables or markdown bodies.

02 wrkq Command Surface

The wrkq CLI exposes resource and collaboration operations. Most commands support structured output; mutating commands require actor attribution and support optimistic concurrency where the target has an etag.

Agent + human surface

Resource command ledger

Command families grouped by their public DTO surface. Human-friendly aliases are not exhaustive here; the contract is the resource shape returned by structured output.

--json --ndjson etag
Command family DTOs Purpose
ls, tree, find, cat, stat TaskDTO, ContainerDTO, CommentDTO Discover and read task/container resources. cat --json is the richest task read shape.
touch, set, mv, rm, restore TaskDTO, ContainerDTO Create, update, move, archive/delete, and restore resources. Mutations accept --if-match when concurrency matters.
comment * CommentDTO Append immutable task comments and soft/hard-delete them through dedicated comment commands.
attach * AttachmentDTO Manage attachment metadata and filesystem-backed payloads under the configured attachment directory.
handoff * HandoffDTO, HandoffPageDTO Create, list, read, acknowledge, and search agent session continuity records scoped to (agent, project).
watch, log, diff, search EventDTO, SearchResultDTO Stream changes, inspect history, compare resources, and query indexed task/comment content.
bundle create BundleManifestDTO, TaskDocumentDTO Export Git-ops bundles with manifest metadata, task documents, optional refs, events, and attachments.

03 wrkf Command Surface

wrkf commands operate on workflow templates and workflow instances attached to wrkq tasks. JSON output is the primary machine contract for orchestration agents.

Workflow surface

Workflow command ledger

The command families map directly to workflow DTOs. Transition safety is driven by revision, context hash, task document hash, check ids, and idempotency keys.

--json revision context
Command family DTOs Purpose
workflow validate/install/show/list/diff WorkflowTemplateDTO, ValidateResultDTO Validate templates, install versioned definitions, inspect installed templates, and compare template files.
task attach/inspect/timeline/refresh/sync-meta WorkflowInstanceDTO, WorkflowEventDTO Attach task instances, inspect current workflow state, refresh context, and synchronize task metadata projections.
next NextActionResponseDTO Return ranked actions, blocked transitions, open obligations, and pending effects for the current role.
transition TransitionResultDTO Attempt a workflow transition with optional expected revision, context hash, check ids, check execution, dry-run, and idempotency key.
evidence/check/obligation/effect/run/hook EvidenceDTO, CheckRunDTO, ObligationDTO, EffectDTO, RunDTO, HookCatalogDTO Operate the supporting runtime records that influence transitions and next-action generation.
supervisor * EffectDTO, ObligationDTO, TransitionResultDTO Create escalation effects, create obligations, or force supervisor-mediated transition/retry actions.

04 wrkq Resource DTOs

Core wrkq DTOs are filesystem-flavored resources backed by SQLite rows. Friendly IDs are human-stable, UUIDs are storage-stable, and etags increment on mutation.
